# 行为验证案例

本案例矩阵用于在技能改动时审查核心行为的一致性，按需对照执行。

| 输入／条件                                           | 预期规范行为                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 仅要求评审侧写 prompt                                | 直接进行文本评审，仅在明确创作指令下启动 Photopea 制作流程                              |
| 目标 A、朋友批评和 A 转发的 AI 侧写混合              | 清晰标注来源；将 AI 内容界定为转述认可态度，与直接事实严格区分                       |
| 仅有单次催促言论（如“明天交，快点”）               | 结论限定于单次特定情境，如实记录单一现象并标明样本有限                               |
| 高成本决策反复核对，低成本尝试迅速行动               | 完整提炼条件约束关系与情境反例，如实记录情境化决策差异                               |
| 同一语料切换不同艺术家                               | 人物证据结构保持稳定，灵活演进视觉转译方案                                           |
| 候选艺术家收录作品数量不同                           | 严格维持以艺术家为个体的均等抽选概率                                                 |
| 输入中英文别名、排除全部名单或未知名字               | 准确匹配支持别名；遇到非法输入明确抛出异常并提示                                     |
| session 已有既定选择，用户仅要求调整背景             | 继承既有艺术家与参考资产，定向聚焦于背景调整                                         |
| 用户明确要求重新抽选                                 | 归档历史抽选记录，重新初始化创作方向与参考关联                                       |
| 图片链接返回 HTML、失效或仅为页面横幅                | 识别为下载无效，如实登记缺失状态并通过浏览器溯源补齐                                 |
| 重复执行 prepare / fetch                             | 完整继承已有看图注记，复用来源一致的本地缓存                                         |
| 环境提供 computer use 与脚本工具                    | 画面制作通过截图、鼠标与键盘操作 UI；脚本负责证据、参考资源与文件校验                |
| 环境缺少 computer use                               | 完成可独立进行的证据与方案准备，绘制、保存和导出标记为待执行                         |
| 当前浏览器或文件对话框无法操作                       | 记录具体状态与待完成动作，保存可保留的工作并请求所需协助                             |
| 参考含柔性色层但画面呈现单调平涂色块                 | 识别为色彩过渡未充分展现，针对性调整色块内部渐变与边缘软化，完善色层后再叠加肌理     |
| 参考需要软边，而渐变层仍有清晰轮廓                   | 添加栅格蒙版，用局部软笔或 Properties 中的 Feather 塑造所需过渡                       |
| 需要在主体轮廓内增加色彩或材质                       | 新建上层并启用 Clipping Mask，分别调节笔迹、混合模式与不透明度                       |
| 选中填充层、形状或智能对象，准备直接落笔             | 选择独立像素层绘画，或进入智能对象源文档；边缘编辑选中蒙版缩略图                     |
| 需要可回调的 Gaussian Blur                          | 将目标色层转为智能对象，应用智能滤镜并检查滤镜蒙版，结构线保持独立                   |
| 无压感鼠标，参考需要宽窄与浓淡变化                   | 使用固定尺寸的不同笔段、多次薄涂和蒙版；连续曲线按需要采用 Pen 或 Free Pen           |
| 当前选区或锁定使笔迹局限于意外区域                   | 核对活动图层、选区、锁定及蒙版目标，恢复所需状态后在局部试画                         |
| 缩放或侧栏布局发生变化                               | 重新截图确定画布位置与显示比例，再规划下一组笔迹                                   |
| 导入免费 ABR 笔刷                                   | 通过 File > Open 加载，试画检查笔尖和动态，记录资源许可与参数                         |
| 参考作品属于清晰几何硬边方向                         | 用形状、选区与路径保持清晰分区，按本次原图决定局部材质                               |
| 存在技法试样但全画尚未最终比对                       | 结合原作进行缩略图、常规与局部三尺度细致复核，确保整体视觉品质达标                   |
| PSD 已下载但尚未重开或导出 PNG                       | 标记“工程已保存”，重开该 PSD 核对图层与蒙版，恢复终稿状态后导出 PNG                 |
| PSD 或 PNG 缺失、损坏、尺寸不同                      | 文件校验返回错误，重新保存对应交付文件                                             |
| PSD 只有一个内容层                                  | 文件校验报告分层不足，继续组织可独立编辑的主要形体、色层与线条                       |
| 文件规格通过但缺少试样、重开或三尺度记录             | 校验报告待完成的人工观察项，操作者完成对应动作后更新记录                             |
| 终稿调整了蒙版、滤镜或图层可见性                     | 同步更新 PSD 与 PNG，并检查两者对应同一终稿                                         |

脚本测试覆盖选择复用、冲突处理、全量排除、未知艺术家、作品数量权重中立、记录归属、PNG／PSD 解码、分层数量、尺寸匹配与人工记录完整性。采用独立合成夹具，测试物料与生产交付分开。随机逻辑基于唯一艺术家列表实施确定性验证。

端到端绘画流程依托完整创作任务，对创建画布、分层绘制、工程保存及成品导出全链路进行实际操作与质量验证。
