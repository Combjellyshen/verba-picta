# 行为验证案例

本案例矩阵用于在技能改动时审查核心行为的一致性，按需对照执行。

| 输入／条件 | 预期规范行为 |
|---|---|
| 仅要求评审侧写 prompt | 直接进行文本评审，仅在明确创作指令下启动 Canva 制作流程 |
| 目标 A、朋友批评和 A 转发的 AI 侧写混合 | 清晰标注来源；将 AI 内容界定为转述认可态度，与直接事实严格区分 |
| 仅有单次催促言论（如“明天交，快点”） | 结论限定于单次特定情境，如实记录单一现象并标明样本有限 |
| 高成本决策反复核对，低成本尝试迅速行动 | 完整提炼条件约束关系与情境反例，如实记录情境化决策差异 |
| 同一语料切换不同艺术家 | 人物证据结构保持稳定，灵活演进视觉转译方案 |
| 候选艺术家收录作品数量不同 | 严格维持以艺术家为个体的均等抽选概率 |
| 输入中英文别名、排除全部名单或未知名字 | 准确匹配支持别名；遇到非法输入明确抛出异常并提示 |
| session 已有既定选择，用户仅要求调整背景 | 继承既有艺术家与参考资产，定向聚焦于背景调整 |
| 用户明确要求重新抽选 | 归档历史抽选记录，重新初始化创作方向与参考关联 |
| 图片链接返回 HTML、失效或仅为页面横幅 | 识别为下载无效，如实登记缺失状态并通过浏览器溯源补齐 |
| 重复执行 prepare / fetch | 完整继承已有看图注记，复用来源一致的本地缓存 |
| 环境同时具备 Canva MCP 与 computer use | 统一使用原生 browser computer use 执行画布操作 |
| 浏览器遇登录拦截或绘图功能受限 | 客观记录环境障碍并提示用户协助，期间并行推进证据与方案准备 |
| 设计已保存但未完成图片下载 | 状态明确标记为“设计已保存，等待图像导出”，完成下载后推进交付 |
| 画布仅导入单张扁平位图 | 将图层状态确切记录为“位图素材”，主要形体通过矢量分层实现可编辑性 |
| 图片尺寸达标但缺失三尺度记录 | 交付脚本报告缺少人工复核项，提示补齐三尺度观察记录后收敛 |

脚本自动化测试应系统覆盖核心行为：选择复用、冲突阻断、全量排除、未知艺术家报错、作品数量权重中立、记录归属校验、损坏图片拦截、比例校验、人工记录完备性检查及有效图像解码。测试执行采用独立测试夹具，测试物料与生产交付严格隔离。随机逻辑基于唯一艺术家列表实施确定性验证。

Canva 端到端流程验证须依托实际授权的完整任务，对创建、绘制、保存及导出全链路进行真实环境观察与确认。
