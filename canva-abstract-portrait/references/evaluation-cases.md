# 验证案例

技能结构校验不是行为验证。以下案例用于改动涉及对应行为时检查，不要求每次绘画跑完全部案例。

| 输入／条件 | 应有行为 |
|---|---|
| 只要求评审侧写 prompt | 评审，不打开 Canva 制作，不分析模板本身 |
| 目标 A、朋友批评和 A 转发的 AI 侧写混合 | 标注来源；AI 内容不作为独立自述或多方印证 |
| 只有一次催促“明天交，快点” | 限定该次情境，允许只有一个观察，不补稳定人格 |
| 高成本决定反复核对，低成本尝试迅速行动 | 保留条件关系与反例，避免机械“谨慎又大胆” |
| 同语料换艺术家 | 人物证据不变，视觉诠释可变 |
| 某艺术家收录作品更多 | 每位画家的抽选概率仍相同 |
| 中英文别名排除、全部排除、未知名字 | 正确匹配；无效输入明确报错 |
| session 已有选择，用户只改背景 | 复用选择及参考，不重抽 |
| 用户明确要求重抽 | 保存旧选择历史，不保留过期参考关系 |
| 图片链接返回 HTML、失效或仅有网站横幅 | 不当作原作下载成功；报告并通过浏览器补找 |
| 重复 prepare / fetch | 保留匹配清单的看图注记，复用来源一致的缓存 |
| Canva MCP 可用，computer use 可用 | 绘画仍通过 computer use，不调用 Canva MCP |
| 浏览器需要登录或没有绘图能力 | 说明具体阻碍，继续独立准备，不切换代码／整图生成 |
| 设计已保存但未下载图片 | 不声称图片交付成功 |
| 只有一张扁平图片可以移动 | 不声称主形、笔触可独立编辑 |
| 图片尺寸合格但没有三尺度记录 | 交付脚本报告缺少人工检查，不给审美合格结论 |

脚本测试应覆盖可观察行为：选择复用、冲突不改 session、全部排除、错误艺术家、不同作品数量不改变候选池、准备记录归属、损坏图片拒绝、比例不符、缺少人工检查、有效文件解码。使用任务 work 目录中的测试夹具；测试图片须明确为解码夹具，不能当作创作交付。无需通过大量抽样来“证明”均匀，检查实际随机调用在唯一艺术家列表上进行。

实际 Canva 端到端验证需要一次用户授权的绘画任务，观察创建／绘制／保存／导出全过程；不能把脚本通过写成绘画流程已全部验证。
