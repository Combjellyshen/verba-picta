# 仅通过 computer use 操作 Canva

## 工具边界

使用全局 computer use，本环境通常为 `mcp__cua_repl`，以当次工具为准。首次调用按工具说明执行，读取返回文档再操作。用户指定浏览器／标签时使用指定对象；否则通过 URL 入口打开 `https://www.canva.com/`。当前公开入口示例：`await cua.getBrowser({ url: "https://www.canva.com/" })`。后续 API 必须来自实际返回文档，不能假设 Playwright 或原生应用接口可用。

不使用 Canva MCP、连接器、REST、Apps SDK、内部接口或后台状态修改。可访问 UI 用语义定位，画布用当前 computer use 支持的鼠标、拖动、键盘和截图。不能把不支持的绘图能力说成已调用。

## 开始与恢复

新作在 UI 创建空白自定义尺寸设计。修改使用用户链接或 session 中实际取得的链接，确认标题、画布、权限和页；不改分享范围。登录需要用户介入时说明具体状态，并继续证据与参考整理。其他设计和账号资料不属于任务。

恢复先读 session 并看当前画面，沿用艺术家、方向和主参考，不重抽。核对 UI 当前是否具备自由绘制／形状、颜色透明度、图层、分组锁定、上传下载。能力影响制作手段，不静默改变随机池。技巧困难时先在同方向内寻找简洁但忠实的结构；主质感不能实现时具体说明缺口。

## 绘制

先搭背景、主色面和一至两个支撑形，缩小确认结构。参考底稿单独管理并记录页／对象，不能误留到导出。

自由曲线优先连续可控笔迹或 UI 支持的曲线编辑。短拖动需测试接缝，增加控制点不自动提升质量。组合形状加同色遮盖可消棱角，但须放大看露缝和遮挡。硬边与笔触变化按所选方向，不为所有画家添加同一旧纸纹理。

先调面积、明度与冷暖，再改个别颜色。局部肌理须统一分辨率、方向、尺度与色调。原作局部裁切／重着色须记录作品 ID、区域及处理。保持主要色面、主形和线条独立，适度分组、锁定，通过 UI 实际选择关键对象确认能改，不追求图层数量。

## 检查、保存和导出

按缩略图、正常尺寸、局部放大三尺度观察，缩放比例据实际 UI 调整。必要截图放任务目录，记录 `{scale, checked_at, observation, fix, screenshot_path}`。资料卡常见问题是提示，不是自动判定。

1. UI 观察保存成功，记时间及真实状态；未看见不可声明已保存。
2. 保存真实设计链接至 `session.canva.design_url`，保留现有权限。
3. 移除／隐藏底稿，只导出成品页；使用下载 UI 获取 PNG 及合理尺寸。
4. 下载落默认目录时，先确认身份，再复制／移动至本任务 outputs，不能误用旧文件。
5. 打开真实导出检查，填写 `export_review`，运行交付脚本。

编辑器截图可做检查，不替代清晰导出。区分设计已保存、结构可编辑、文件已下载、文件已打开四个状态。不引入 Canva MCP 的交易／提交协议。

## session 字段

执行者维护 `stage`、`canvas: {width,height}`、`core_observations`，以及：

```json
{
  "canva": {
    "design_url": "实际取得的链接",
    "save_observed_at": "实际时间",
    "save_observation": "真实 UI 状态",
    "editable_elements": [],
    "reference_underlay_status": "removed / hidden / not_used"
  },
  "quality_checks": [],
  "export_review": {"viewed_at": "实际时间", "observation": "导出观察"}
}
```

示例字符串不能作为完成记录。随机脚本只写 selection，参考脚本只写方向和清单，不替执行者填写观察。
