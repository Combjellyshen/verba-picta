# 基于 Computer Use 的 Canva 操作规范

## 工具边界

交互环境采用全局 computer use（通常为 `mcp__cua_repl`，以实际注入工具为准）。首次调用遵循工具文档说明，依据返回的交互上下文推进操作。若用户指定了浏览器或标签页，直接接管指定对象；默认通过 URL 入口打开 `https://www.canva.com/`（如 `await cua.getBrowser({ url: "https://www.canva.com/" })`）。后续操作严格调用当前交互环境实际支持的 API。

全部操作统一通过原生浏览器 UI 语义定位、鼠标点击、拖拽绘制、键盘输入及屏幕截图完成，严格依托当前环境具备的真实视觉与输入能力，杜绝虚报未执行的绘图动作。

## 开始与恢复

新作在 UI 中创建指定尺寸的空白画布；修改任务加载用户提供或 session 中记录的既有设计链接，核验标题、尺寸、权限及操作页码，严格维持原有分享范围设置。若遇登录拦截，明确陈述所需操作并请求用户协助，期间并行推进证据整理与艺术参考检索。操作范围严格限定于当前肖像设计项目。

中断恢复时优先读取 `session.json` 并审阅当前画布状态，完整继承既定的艺术家、风格方向与核心参考体系。核验当前 UI 支持的绘图功能（自由绘制、形状、透明度、图层管理、分组锁定及导入导出）。依工具实际能力选用适合的制作手段，保持既定随机池的稳定性；若遇复杂技巧限制，优先提炼并实现该方向核心的简约骨架结构，并在报告中客观说明技术折衷。

## 绘制

优先构建背景底色、主体色块及主要支撑形，缩小视距审定整体骨架平衡。参考底稿独立管理并记录对应图层/对象，在最终导出前确保完全清除或隐藏。

自由曲线优先使用平滑连续线或可调曲线；短线条拼接需重点检验接缝连续性与锚点整洁度。组合形体可通过同色遮罩优化转折棱角，并在放大视距下细致检查边缘贴合度。硬边与笔触质感严格契合所选艺术家的语言特性，杜绝模式化添加千篇一律的背景纹理。

调色遵循“整体面积与明度冷暖优先、局部微调在后”的原则。局部肌理素材需确保分辨率、纹理走向、尺度与全画色调融洽协调。涉及原作局部的裁切或重着色，如实记录作品 ID、取样区域及处理参数。主要色面、核心形体与线性骨架保持图层独立，合理执行分组与适度锁定，在 UI 中逐项点选验证图层可编辑性，追求清晰的组织逻辑而非盲目堆叠图层。

## 检查、保存和导出

依次在缩略图、正常视距与局部放大三尺度下审视画面，记录结构化检查结果 `{scale, checked_at, observation, fix, screenshot_path}`。资料卡提示项作为重点复核指引，由人工视觉核验得出明确判定。

1. 在 UI 明确观测到保存成功状态后，记录时间戳与客观状态信息。
2. 将实际生效的设计链接存入 `session.canva.design_url`，保持既有权限配置。
3. 确认底稿已彻底清理或隐藏后，指定导出目标成品页；通过下载功能获取满足尺寸规格的高清 PNG。
4. 文件下载至系统目录后，核验文件创建时间与名称，准确归档至任务 `outputs/` 目录。
5. 本地实际打开导出的图像文件进行终审检查，完整填写 `export_review`，再执行交付校验脚本。

过程截图作为质量追溯凭据，最终交付必须提供完整的独立高分辨率导出文件。明确界定并分别记录设计保存、图层编辑、文件下载与本地核验四个阶段性状态。

## session 字段

执行者维护 `stage`、`canvas: {width,height}`、`core_observations`，以及：

```json
{
  "canva": {
    "design_url": "实际取得的链接",
    "save_observed_at": "实际时间",
    "save_observation": "真实 UI 状态",
    "editable_elements": [],
    "reference_underlay_status": "removed / hidden / not_used"
  },
  "quality_checks": [],
  "export_review": {"viewed_at": "实际时间", "observation": "导出观察"}
}
```

各字段必须填写真实观测到的时间戳与具体内容，杜绝占位符残留。脚本模块各司其职：抽选脚本记录 selection，参考脚本管理方向与资产清单，主观视觉观察由执行者在完成审阅后如实录入。
